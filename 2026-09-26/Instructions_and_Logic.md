# Урок: перша кулеметна вежа

26.09.2026. Godot 4 / C#. Пиши код сам за цим уроком; повні скрипти для звіряння лежать у `Final_Solution.md`. Робочі скрипти та сцени не змінені автоматично.

## 1. Результат і межі уроку

Встановлена вручну вежа знаходить найближчого живого ворога в радіусі 220 пікселів. Кожні 0,5 секунди вона завдає 10 шкоди. Ворог має 30 здоров’я й гине після трьох влучань. Це навчальні параметри, а не остаточний баланс. Коротка жовта лінія показує постріл, зелене коло — радіус.

Постріл миттєвий: лінія лише візуалізація, фізичної кулі немає. Стіни поки не блокують стрільбу. Вежа не змінює шлях ворогів; став її збоку від проходу. Обертання спрайта, Tesla й інтеграція карток — наступні кроки.

У папці `2026-09-21` уже є окремий урок карток і розміщення. Якщо ти його ще не виконав, для цього уроку він не потрібний. Поточна сцена ворога — `res://runner.tscn`, скрипт — `res://enemies/Enemy.cs`.

## 2. Як пов’язані вузли й код

Enemy відповідає за свій рух, здоров’я і видалення. MachineGunTower відповідає за вибір цілі й частоту атак. Вежа викликає `enemy.TakeDamage(Damage)`, але сама не видаляє ворога.

Вороги зараз Node2D без фізичних тіл. Тому використаємо групу `enemies`: це список вузлів у SceneTree, а не папка Enemies на рівні. Метод `AddToGroup("enemies")` реєструє ворога; після видалення вузол зникає з групи автоматично. Area2D і CollisionShape2D для цього варіанта не потрібні.

Важливо розрізняти два завершення життя ворога: прибуття викликає ReachedBase, загибель — ні. Інакше вбиті вороги збільшуватимуть лічильник тих, хто дістався бази.

## 3. Додай здоров’я самостійно

1. Зупини гру F8. Відкрий `enemies/Enemy.cs`.
2. Поряд зі Speed оголоси експортовану властивість MaxHealth зі значенням 30. Export дозволяє змінювати параметр у Inspector.
3. Додай Health із публічним читанням і приватним записом: `public int Health { get; private set; }`. Зовнішній код має завдавати шкоди через метод, а не довільно змінювати число.
4. Додай обчислювану властивість CanBeTargeted. Вона істинна лише коли `_finished` хибне, Health більше нуля й вузол не очікує видалення.
5. У `_Ready()` виклич AddToGroup із назвою `enemies`.
6. У Setup після скидання `_finished` встанови Health у `Math.Max(1, MaxHealth)`.
7. Напиши `public void TakeDamage(int amount)`. Спочатку вийди, якщо ціль неактивна або amount <= 0. Потім відніми шкоду, обмеживши результат нулем. Виведи Health через GD.Print для перевірки. Якщо залишився нуль, спочатку встанови `_finished = true`, потім виклич QueueFree.

QueueFree видаляє вузол наприкінці кадру. Прапорець потрібен негайно: друга вежа того самого кадру вже не повинна стріляти в загиблого. Не викликай Finish із TakeDamage — Finish означає прибуття до бази.

## 4. Створи сцену вежі

1. Scene → New Scene → Other Node → Node2D. Назви корінь `MachineGunTower`.
2. Збережи сцену як `res://towers/machine_gun.tscn`.
3. Додай дитину Sprite2D. Перетягни `res://towers/machine_gun.png` у Texture.
4. Зменшуй Scale тільки у Sprite2D, поки зображення не стане приблизно 64–96 пікселів завширшки. Корінь залиш із Scale (1, 1), щоб коло радіуса відповідало світовим відстаням.
5. На корені встанови Ordering → Z Index = 5.
6. Прикріпи до кореня C#-скрипт `res://towers/MachineGunTower.cs`. Клас має називатися MachineGunTower. Якщо сцена вже створена за попереднім уроком, відкрий її та прикріпи скрипт до її кореня.

Дерево: MachineGunTower (Node2D + скрипт) → Sprite2D. Таймер окремим вузлом тут не потрібний: відлік ведемо через delta.

## 5. Напиши алгоритм вежі

Оголоси три Export-властивості: AttackRange = 220f, Damage = 10, ShotInterval = 0.5. Додай приватні поля `_cooldown`, `_flashRemaining` типу double та `_shotEnd` типу Vector2.

У `_Ready` перевір, що всі три параметри додатні. Якщо ні — GD.PushError і SetPhysicsProcess(false), щоб помилкова конфігурація не запускала атаки.

Метод FindTarget повертає Enemy або null. Почни з порожньої цілі й максимальної відстані AttackRange * AttackRange. Перебери GetTree().GetNodesInGroup("enemies"). Пропускай інші типи, невалідні об’єкти й ворогів із CanBeTargeted = false. Порівнюй `GlobalPosition.DistanceSquaredTo(enemy.GlobalPosition)` із поточним мінімумом. Якщо відстань менша або рівна, запам’ятай ворога й новий мінімум.

Квадрат відстані дозволяє порівнювати близькість без квадратного кореня. Обидві позиції мають бути GlobalPosition: локальні координати дітей різних батьків можуть відрізнятися. Перебір групи простий для перших п’яти ворогів; для великих хвиль згодом розглянемо просторовий пошук.

Псевдокод `_PhysicsProcess(delta)`:

```text
зменшити час видимості лінії до мінімуму 0
замовити перемальовування QueueRedraw
зменшити cooldown до мінімуму 0
якщо cooldown > 0: вийти
знайти ціль
якщо її немає: вийти
зберегти локальну позицію кінця лінії через ToLocal
завдати Damage через TakeDamage
показувати лінію 0,08 секунди
встановити cooldown = ShotInterval
```

delta — тривалість фізичного кадру в секундах. Поки цілі немає, вежа залишається готовою до пострілу. Ціль обирається заново перед кожним пострілом. За великої затримки кадру цей простий варіант робить максимум один постріл за кадр, без накопиченої черги атак.

У `_Draw()` намалюй коло через DrawArc із центром Vector2.Zero, кутами 0 і Mathf.Tau та радіусом AttackRange. Якщо `_flashRemaining > 0`, намалюй DrawLine від Vector2.Zero до `_shotEnd`. Методи малювання використовують локальні координати; саме тому вище потрібен ToLocal. Повний синтаксис дивись у розв’язку після своєї спроби.

## 6. Підключи й запусти

1. Збери C#-проєкт кнопкою Build. Збережи скрипти й сцену.
2. Відкрий `levels/level_01.tscn`. Додай до Level01 вузол Node2D із назвою Towers, якщо його ще немає. Залиш його трансформацію початковою.
3. Перетягни `towers/machine_gun.tscn` на Towers. Постав екземпляр на підлозі збоку від маршруту Spawn → Base, приблизно за 100 пікселів від проходу.
4. Перевір у Inspector вежі Attack Range = 220, Damage = 10, Shot Interval = 0.5. У кореня `runner.tscn` має з’явитися Max Health = 30.
5. Збережи сцени. Запускай рівень через F6. Зелений радіус видно під час запуску; перемісти вежу в редакторі, якщо маршрут не потрапляє всередину.

Якщо урок карток уже підключений: признач цю сцену в Machine Gun Scene контролера розміщення. Для перевірки карток прибери вручну встановлену тестову вежу — контролер із попереднього уроку не реєструє її клітинку як зайняту автоматично.

## 7. Перевір поведінку

- Один ворог: тимчасово Spawn Count = 1. У радіусі очікуй здоров’я 20 → 10 → 0. Для гарантованих трьох пострілів можна тимчасово зменшити Speed у runner до 30.
- Смерть: ворог зникає; повідомлення `enemy reached base` для нього не з’являється.
- Поза радіусом: перенеси вежу далеко від проходу. Ворог доходить до Base як раніше.
- Кілька ворогів: поверни Spawn Count = 5. Лінія має вести до найближчого живого ворога в радіусі.
- Дві вежі: дублюй екземпляр Ctrl+D. Загибель ворога не повинна викликати помилку звернення до видаленого об’єкта.
- Невірні параметри: встанови Shot Interval = 0 й перезапусти. В Output має бути помилка конфігурації, атаки вимкнені. Після перевірки поверни 0.5, Speed = 100 і Spawn Count = 5.

Якщо вежа не стріляє, перевір скрипт на корені, назву групи, виклик Setup і радіус. Якщо зміни Enemy не видно, перевір, що Enemy Scene у спавнері посилається на `res://runner.tscn`.

## 8. Питання для самоперевірки

Чому вежа не викликає QueueFree на ворогові сама? Чому загибель не повинна викликати ReachedBase? Чому для вибору цілі потрібні світові координати, а для лінії — локальні? Що станеться, якщо масштабувати корінь вежі?
