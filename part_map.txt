ІНСТРУКЦІЯ — СТВОРЕННЯ ПЕРШОЇ МАПИ ЧЕРЕЗ TILEMAP
Оновлено: 19.09.2026, після уточнення автора.

ЗАРАЗ РОБИМО МАПУ
Твій порядок роботи: спочатку вручну малюємо мапу через TileMap,
потім переходимо до маршрутів монстрів. Нижче — послідовність натискань
для мапи. Наприкінці збережено план решти першого рівня.
Розмір і розташування перешкод у прикладі — запропонований навчальний
макет: після освоєння малювання ти можеш намалювати власну форму.

У сучасному Godot 4 потрібний вузол називається TileMapLayer, а нижня
панель малювання — TileMap. Саме через неї ти розставлятимеш тайли.
Старий вузол TileMap позначений deprecated; його тут не використовуємо.
Довідка: https://docs.godotengine.org/en/stable/classes/class_tilemap.html

Назви кнопок наведені для англомовного інтерфейсу. Розташування панелей
описане для стандартного компонування Godot. Я звірив назви з документацією,
але не бачу твого вікна редактора; у різних версіях вигляд значків відрізняється.
ЛКМ = ліва кнопка миші. ПКМ = права. Натискання «коліщатка» = середня кнопка.
Коли написано «введи значення», клацни поле, Ctrl+A, введи число, Enter.

0. ВІДКРИТИ ПРОЄКТ І ЗНАЙТИ ПАНЕЛІ
0.1. Запусти Godot. Якщо проєкт game-4 уже відкритий, переходь до 0.5.
0.2. У менеджері проєктів натисни Import.
0.3. У вікні вибору файлів відкрий папку game-4, вибери project.godot,
	 натисни Open, а потім Import & Edit, якщо з'явиться ця кнопка.
0.4. Дочекайся завершення імпорту зображень.
0.5. Знайди ліворуч угорі Scene — це дерево об'єктів поточної сцени.
0.6. Ліворуч унизу знайди FileSystem — це папки й файли проєкту.
	 res:// — корінь game-4, а не окрема папка на комп'ютері.
0.7. Праворуч знайди Inspector — властивості вибраного об'єкта.
0.8. Угорі по центру натисни 2D.
0.9. Якщо панелі переставлені й ти їх не знаходиш, відкрий Editor >
	 Editor Layout > Default. Це поверне стандартне компонування.

Результат: бачиш Scene, FileSystem, Inspector і центральне поле 2D.

1. ПІДГОТУВАТИ КАРТИНКУ ТАЙЛІВ — ОДИН РАЗ
TileMap малює мапу з маленьких фрагментів картинки. Наша картинка вже є:
res://tiles/metro_atlas.png. У ній 4 × 4 фрагменти, але розмір 1254 × 1254.
Для першого макета зробимо копію 256 × 256, щоб кожен фрагмент займав
64 × 64. Це підготовка картинки; саму мапу малюватимеш у Godot.
Масштабування не прибере намальовані рамки навколо плит і не зробить
графіку безшовною. Для навчального макета залишаємо ці видимі стики.

Нижче конкретний спосіб через GIMP. Якщо він уже встановлений — 1.3.
1.1. Відкрий у браузері https://www.gimp.org/downloads/.
1.2. Вибери завантаження для своєї ОС і встанови GIMP за інсталятором
	 або інструкцією на цій сторінці. Запусти GIMP.
1.3. У GIMP натисни File > Open (Ctrl+O).
1.4. Вибери файл game-4/tiles/metro_atlas.png і натисни Open.
1.5. У верхньому меню натисни Image > Scale Image.
1.6. Перевір, що одиниці Width і Height — px, тобто пікселі.
1.7. Залиш ланцюжок між Width і Height з'єднаним, щоб зберегти пропорції.
1.8. У Width введи 256, натисни Tab. Height теж має стати 256.
1.9. У Interpolation вибери Cubic. Натисни Scale.
1.10. Натисни File > Export As (Ctrl+Shift+E).
1.11. Відкрий папку game-4/tiles, у полі назви введи metro_atlas_64.png.
1.12. Натисни Export. У вікні параметрів PNG ще раз натисни Export.
      Не замінюй metro_atlas.png: це вихідна картинка.
1.13. Повернися в Godot. У FileSystem розгорни tiles стрілкою ліворуч.
      Дочекайся появи metro_atlas_64.png.

Результат: у tiles є оригінал і нова копія metro_atlas_64.png.
Довідка GIMP: https://docs.gimp.org/3.0/en/gimp-image-scale.html

2. ЗРОБИТИ ПАПКИ Й ЗБЕРЕГТИ СЦЕНУ
2.1. У FileSystem клацни ПКМ по res://.
2.2. У меню вибери Create New > Folder. Введи scenes, натисни Create.
2.3. ПКМ по scenes > Create New > Folder. Введи levels, натисни Create.
2.4. ПКМ по res:// > Create New > Folder. Створи resources.
2.5. ПКМ по resources > Create New > Folder. Створи tilesets.
     Якщо папка вже існує, повторно створювати її не потрібно.
2.6. У FileSystem двічі клацни node_2d.tscn.
2.7. У Scene вибери верхній Node2D, натисни F2, введи Level01, Enter.
2.8. У верхньому меню натисни Scene > Save Scene As.
2.9. У вікні збереження відкрий res://scenes/levels.
2.10. У полі імені введи level_01.tscn, натисни Save.

Результат: угорі відкрита вкладка level_01, у Scene один корінь Level01.
Початкова node_2d.tscn залишається окремим файлом.

3. ДОДАТИ ШАР ПІДЛОГИ
3.1. У Scene клацни Level01.
3.2. Натисни «+» над деревом Scene — Add Child Node (або Ctrl+A).
3.3. У пошуку вікна введи TileMapLayer.
3.4. Вибери саме TileMapLayer у списку й натисни Create.
3.5. Новий вузол має бути під Level01, з відступом праворуч.
3.6. Вибери його, натисни F2, введи Ground, Enter.
3.7. У правому Inspector розгорни Transform. Залиш Position x=0, y=0,
     Rotation=0, Scale x=1, y=1. Якщо вони вже такі — нічого не змінюй.

Результат: Level01 > Ground. Ground — шар, на якому малюватимемо підлогу.

4. СТВОРИТИ НАБІР ТАЙЛІВ — TILESET
4.1. Вибери Ground у Scene.
4.2. У Inspector знайди Tile Set. Праворуч від порожнього поля натисни
     маленьку стрілку меню ресурсу, вибери New TileSet.
4.3. Клацни створений ресурс TileSet, щоб відкрити його властивості.
4.4. У Tile Size введи x=64, y=64. Tile Shape залиш Square.
4.5. Унизу редактора натисни TileSet. Якщо панель низька, потягни
     її верхню межу вгору — має бути зручно бачити картинку.
4.6. Із FileSystem перетягни tiles/metro_atlas_64.png у нижню панель
     TileSet. Не кидай картинку в центральне поле 2D — там створиться Sprite2D.
4.7. На запит автоматично створити тайли натисни Yes.

Результат: у TileSet бачиш картинку, розділену на 4 стовпці й 4 рядки.
Довідка: https://docs.godotengine.org/en/stable/tutorials/2d/using_tilesets.html

5. ПЕРЕВІРИТИ АТЛАС І ЗБЕРЕГТИ TILESET
5.1. У списку джерел ліворуч усередині нижньої панелі TileSet клацни
     джерело з metro_atlas_64.png. Для властивостей атласу вибери Setup.
5.2. У його властивостях перевір:
       Texture — metro_atlas_64.png;
       Texture Region Size — x=64, y=64;
       Margins — x=0, y=0;
       Separation — x=0, y=0;
       Use Texture Padding — увімкнено.
     Це властивості атласу в нижній панелі, а не Transform вузла праворуч.
5.3. Якщо бачиш багато дрібних клітинок, виправ Texture Region Size.
     Якщо після виправлення тайли відсутні, натисни меню з трьома крапками
     в редакторі атласу > Create Tiles in Non-Transparent Texture Regions.
5.4. У Scene знову вибери Ground. У Inspector біля ресурсу Tile Set
     натисни стрілку меню > Save (або Save As, якщо ресурс уже збережений).
5.5. У вікні вибери res://resources/tilesets, введи metro.tres, натисни Save.
5.6. Натисни Ctrl+S для збереження сцени.

Результат: у FileSystem є resources/tilesets/metro.tres.
Параметри атласу: https://docs.godotengine.org/en/stable/classes/class_tilesetatlassource.html
Параметри TileSet: https://docs.godotengine.org/en/stable/classes/class_tileset.html

6. ДОДАТИ ІНШІ ШАРИ TILEMAP
Потрібно ще три вузли. Додавай їх до Level01, а не всередину Ground.
6.1. Вибери Level01 > «+» > знайди TileMapLayer > Create.
6.2. F2 > введи Walls > Enter.
6.3. У FileSystem розгорни resources/tilesets.
6.4. Перетягни metro.tres у поле Tile Set вузла Walls в Inspector.
6.5. Знову вибери Level01 > «+» > TileMapLayer > Create.
6.6. F2 > введи Details > Enter. Перетягни metro.tres у його Tile Set.
6.7. Знову вибери Level01 > «+» > TileMapLayer > Create.
6.8. F2 > введи BuildZones > Enter. Перетягни metro.tres у його Tile Set.
6.9. По черзі вибери кожен шар. В Inspector розгорни Ordering і встанови
     Z Index: Ground=0, Details=1, BuildZones=2, Walls=3.
     Якщо розділ не видно, введи z_index у пошук Inspector, задай значення,
     а потім очисть пошук хрестиком.
6.10. У кожного шару залиш Transform > Position=(0,0), Scale=(1,1).
6.11. Ctrl+S.

Дерево має виглядати так, усі чотири шари на одному рівні відступу:
  Level01
    Ground
    Walls
    Details
    BuildZones

Результат: підлога, декор, позначення будівництва та стіни малюються окремо.
Спільний metro.tres означає, що виправлення одного тайла діє на всі шари.
Довідка: https://docs.godotengine.org/en/stable/classes/class_tilemaplayer.html

7. НАВЧИТИСЯ СТАВИТИ Й СТИРАТИ КЛІТИНКУ
7.1. У Scene вибери Ground.
7.2. Унизу натисни TileMap — тепер саме TileMap, а не TileSet.
7.3. У нижній палітрі вибери атлас metro_atlas_64.png, якщо він не вибраний.
7.4. Один раз клацни його верхню ліву плитку — звичайний бетон.
     Не тягни мишею по палітрі: так можна вибрати одразу кілька плиток.
7.5. У панелі інструментів TileMap вибери Paint — значок пензля/олівця.
     Наведи курсор на значок і зачекай підказку, щоб перевірити назву.
7.6. Перемісти курсор у центральне поле 2D: під ним має з'явитися плитка.
7.7. Клацни ЛКМ — плитка поставиться. Проведи із затиснутою ЛКМ —
	 намалюєш кілька плиток. ПКМ у режимі малювання стирає плитку.
7.8. Натисни Ctrl+Z, щоб скасувати пробне малювання.
7.9. Коліщатко змінює масштаб огляду. Затиснуте коліщатко й рух миші
	 пересувають огляд; саму мапу це не зміщує.

Дві різні координатні сітки:
  — У палітрі атласу (0,0) — картинка бетону, (3,2) — картинка блоку.
  — На мапі (0,0) — місце, куди ставиш будь-яку вибрану картинку.
Клітинки мапи рахуємо від нуля. x зростає праворуч, y — униз.
Перетин кольорових осей у 2D — світова точка (0,0). Клітинка (0,0)
лежить одразу праворуч і нижче цього перетину. Її центр — (32,32) px.
За масштабу 100% одна клітинка має 64 екранні пікселі; за іншого масштабу
орієнтуйся на сітку, а не на фізичні пікселі монітора.

Довідка з інструментами: https://docs.godotengine.org/en/stable/tutorials/2d/using_tilemaps.html

8. НАМАЛЮВАТИ ПІДЛОГУ 24 × 14
8.1. Переконайся: у Scene вибрано Ground, унизу TileMap, у палітрі бетон.
8.2. На панелі малювання вибери Rectangle — інструмент прямокутника.
8.3. Наведи курсор у клітинку (0,0), тобто праворуч-унизу від початку осей.
8.4. Затисни ЛКМ і протягни до клітинки (23,13): це 24-та клітинка вправо
	 і 14-та вниз, якщо рахувати початкову клітинку як першу.
8.5. Перевір прямокутний попередній перегляд і відпусти ЛКМ.
8.6. Якщо помилився розміром, Ctrl+Z і повтори. Межі готового поля у світових
	 координатах мають бути x=0..1536, y=0..896.
8.7. Поверни інструмент Paint. У палітрі вибери потрісканий бетон —
	 другий тайл першого рядка. Постав його в кілька клітинок усередині.
8.8. Так само можна додати третій і четвертий тайли першого рядка.
	 Усі вони залишаються підлогою. Не став сюди тайли стін.
8.9. Ctrl+S.

Результат: суцільний прямокутник підлоги, без порожніх клітинок усередині.

9. НАМАЛЮВАТИ СТІНИ
Для першої перевірки використаємо суцільний блок: четвертий тайл третього
рядка, координата В АТЛАСІ (3,2). Він зручний для повністю зайнятої клітинки.
9.1. У Scene вибери Walls. Унизу залиш TileMap.
9.2. У палітрі клацни тайл (3,2). Увімкни Rectangle.
9.3. Намалюй верхній ряд: затисни ЛКМ у клітинці мапи (0,0), протягни
	 до (23,0), відпусти. Під час перетягування залишайся в одному рядку.
9.4. Намалюй нижній ряд так само: від (0,13) до (23,13).
9.5. Намалюй лівий край: від (0,1) до (0,12).
9.6. Намалюй правий край: від (23,1) до (23,12).
9.7. Намалюй центральну перешкоду: від (10,4) до (13,9).
	 Вийде прямокутник шириною 4 клітинки та висотою 6.
9.8. Ctrl+S.

Схема прикладу. Кожен символ — клітинка, у кожному рядку 24 символи.
# — Walls, крапка — вільна підлога; S і B позначимо далі, це не стіни.
Рядки зверху вниз: y=0..13.

#......................#
#.........####.........#
#.........####.........#
#.........####.........#
#.S.......####.......B.#
#.........####.........#

Результат: між лівою і правою частиною є верхній та нижній проходи.
У цьому макеті вороги з'являтимуться всередині рамки, у S, тому отвір
у зовнішній стіні для запуску цього прикладу не потрібний.

10. ЗРОБИТИ СТІНИ ФІЗИЧНО ТВЕРДИМИ
Це налаштує колізію. Пошук маршрутів підключатимемо окремо після мапи.
10.1. Вибери Walls > Inspector > клацни ресурс Tile Set.
10.2. Розгорни Physics Layers, натисни Add Element.
10.3. У новому елементі 0 залиш Collision Layer з увімкненим лише числом 1.
      Колізійні маски майбутніх ворогів мають бачити цей шар.
10.4. Унизу відкрий TileSet, вибери атлас, потім режим Select.
10.5. Клацни тільки використаний нами блок (3,2) у картинці атласу.
10.6. У властивостях вибраного тайла всередині TileSet розгорни
      Physics > Physics Layer 0. Знайди редактор полігона цього тайла.
10.7. Клацни порожнє місце біля його мініатюри для фокусу й натисни F:
	  має з'явитися прямокутний контур за розміром тайла.
	  Якщо F не спрацювало, у цьому редакторі вибери інструмент нового
	  полігона, клацни чотири кути плитки по колу, потім першу точку,
	  щоб замкнути контур. Для нашого макета блок займає всю клітинку.
10.8. У Scene вибери Walls. В Inspector знайди Physics > Collision Enabled:
	  залиш увімкненим. Не плутай це з Physics Layers усередині TileSet.
10.9. Ctrl+S. Якщо біля metro.tres є незбережені зміни, вибери цей ресурс
	  і збережи через його меню Save.

Результат: тільки блок має колізію, бетон і рейки не стають стінами.
Перевірка рухом буде можлива, коли додамо фізичного ворога. Зараз можна
перевірити наявність контуру, але це ще не перевірка поведінки монстрів.
Якщо потім використаєш інші три картинки стін, повтори 10.5–10.7 для них.
Довідка: https://docs.godotengine.org/en/stable/tutorials/2d/using_tilesets.html#adding-collision-navigation-and-occlusion-to-the-tileset

11. ПОЗНАЧИТИ ВХІД І БАЗУ
11.1. Вибери Level01 > «+» > у пошуку Marker2D > Create.
11.2. F2 > введи Spawn > Enter.
11.3. В Inspector відкрий Transform > Position: x=160, y=480.
	  Це центр клітинки (2,7).
11.4. Знову вибери Level01 > «+» > Marker2D > Create.
11.5. F2 > введи Base > Enter.
11.6. Transform > Position: x=1376, y=480. Це центр клітинки (21,7).

Marker2D видно в редакторі, але не видно в запущеній грі. Тому додамо
видимі тимчасові позначення тайлами:
11.7. У Scene вибери Details, унизу TileMap, інструмент Paint.
11.8. У палітрі вибери попереджувальні смуги — четвертий тайл четвертого
	  рядка, координата атласу (3,3). Клацни на мапі клітинку (2,7).
11.9. У палітрі вибери люк — третій тайл четвертого рядка, (2,3).
	  Клацни на мапі клітинку (21,7).
11.10. Ctrl+S.

Результат: смуги означають місце появи монстрів, люк — базу.
Base поки лише маркер і картинка люка. Здоров'я бази тут ще не реалізовано.

12. ПОЗНАЧИТИ МІСЦЯ ВЕЖ І ДОДАТИ ДЕКОР
12.1. Вибери BuildZones > нижня панель TileMap > Paint.
12.2. У палітрі вибери сталеву плиту: третя плитка другого рядка, (2,1).
12.3. Постав по одній плитці в клітинки мапи (7,3), (16,3), (7,10), (16,10).
      Це чотири запропоновані місця веж, з боків від центральної перешкоди.
12.4. Вибери Details. Для декору вибери в палітрі горизонтальний дренаж
      (0,1) і постав його у клітинки мапи (4,2), (5,2), (6,2).
12.5. Не малюй декор поверх люка, Spawn чи позначених місць веж.
12.6. Ctrl+S.

Результат: читабельна мапа з підлогою, стінами, входом, базою і місцями веж.
BuildZones зараз лише дані й видиме позначення. Натискання на плиту
не побудує вежу, доки не буде реалізований режим будівництва.

13. НАЛАШТУВАТИ КАМЕРУ ТА ВІКНО
13.1. У Scene вибери Level01 > «+» > Camera2D > Create.
13.2. В Inspector > Transform > Position введи x=768, y=448.
13.3. Знайди Enabled і залиш увімкненим.
13.4. Zoom залиш x=1, y=1. Position Smoothing > Enabled залиш вимкненим.
13.5. У верхньому меню натисни Project > Project Settings.
13.6. У пошуку цього вікна введи viewport_width. Встанови 1536.
13.7. Заміни пошук на viewport_height. Встанови 896.
13.8. Якщо наступні параметри не показуються, увімкни Advanced Settings.
13.9. Знайди window_width_override, введи 1152.
13.10. Знайди window_height_override, введи 672.
       Це розмір вікна; логічний розмір мапи залишається 1536 × 896.
13.11. Знайди stretch/mode, вибери canvas_items.
13.12. Знайди stretch/aspect, вибери keep, щоб у цьому прикладі вся мапа
       зберігала пропорції при зміні розміру вікна.
13.13. Натисни Close, потім Ctrl+S.

Результат: камера в центрі поля; вікно меншого розміру показує всю мапу.

14. ЗАПУСТИТИ Й ПЕРЕВІРИТИ
14.1. Угорі вибери вкладку level_01, натисни F6 (Run Current Scene).
14.2. У вікні гри перевір чотири зовнішні стіни: усі мають потрапляти в кадр.
14.3. Перевір центральний блок, два обходи, смуги зліва, люк справа
      і чотири металеві плити. Картинка поки нерухома — це очікувано.
14.4. Повернися до редактора, натисни F8 для зупинки.
14.5. У FileSystem знайди scenes/levels/level_01.tscn, клацни ПКМ і вибери
      Set As Main Scene. Тепер F5 запускатиме цей рівень.
14.6. Натисни F5, перевір, що відкривається та сама мапа. Зупини через F8.
14.7. Унизу відкрий Debugger: перевір, що немає червоних помилок.
14.8. Ctrl+S.

Мапа готова до наступного етапу, якщо:
[ ] Вона намальована вручну через TileMap і збережена у level_01.tscn.
[ ] Ground, Walls, Details, BuildZones — окремі TileMapLayer зі спільним TileSet.
[ ] Підлога суцільна, у центральної перешкоди є два обходи.
[ ] На тайлі блоку налаштований полігон колізії.
[ ] Spawn і Base стоять у центрах потрібних клітинок.
[ ] F5 показує всю мапу, немає помилок завантаження.

15. ЯКЩО ЩОСЬ НЕ ВИХОДИТЬ
— Немає вкладки TileMap: вибери Ground/Walls у Scene; переконайся,
  що в Inspector > Tile Set призначено metro.tres.
— Бачиш картинку атласу як один великий об'єкт: імовірно, перетягнув PNG
  у поле 2D. Якщо це остання дія, Ctrl+Z. Повтори 4.6 у нижній панелі TileSet.
— Курсор малює відразу кілька різних тайлів: у палітрі один раз клацни
  одну плитку без перетягування; вимкни випадковий вибір, якщо його увімкнув.
— Стирається підлога замість стіни: у Scene вибери Walls і стирай на ньому.
— Зникли всі шари після зміни TileSet: перевір Texture Region Size й джерело
  атласу. Не видаляй джерело атласу, яким уже намальована мапа.
— При запуску порожньо: F8; Camera2D > Enabled увімкнено, Position=(768,448);
  Ground > Enabled увімкнено; запускай вкладку level_01 через F6.
— У грі немає хрестиків Spawn/Base: так працює Marker2D. Видимі позначення
  додаються на Details у кроках 11.7–11.9.
— Між плитами видно темні рамки: вони намальовані у вихідному PNG.
  Параметр Texture Padding не прибирає рамки з самої картинки.

ДАЛІ — ПЛАН ПОВНОГО РІВНЯ, А НЕ ПОКРОКОВИЙ УРОК
Нижче збережено майбутні задачі попередньої версії, щоб не загубити загальний
план. Не потрібно зараз намагатися виконати їх як інструкцію: там немає
готового коду. Наступний практичний розділ після мапи — маршрути монстрів;
його потрібно оформити так само докладно, з натисканнями та повним кодом,
коли переходимо до цього етапу. Наявність цього плану не означає, що рівень
уже функціонує як tower defense.

ПЛАН А. МАРШРУТИ МОНСТРІВ
Для клітинкової мапи з барикадами пропоную AStarGrid2D. Один намальований
Path2D зручний для незмінної траси, але сам не забезпечує обхід нових перешкод.
Не вважай намальовані стіни автоматично врахованими в пошуку шляху.

Створи scripts/grid_navigation.gd і вузол GridNavigation у Level01.
Обов'язки майбутнього скрипта:
  • Задати область сітки, розмір клітинки та викликати update().
  • Після update() позначити непрохідними стіни й клітинки без підлоги.
  • Для першого тесту заборонити діагоналі, щоб не зрізати кути стін.
  • Обчислювати шлях між клітинками Spawn і Base.
  • Перетворювати клітинки на центри в координатах світу через
    Ground.map_to_local() і Ground.to_global(); вхідні позиції — через
    Ground.to_local() і Ground.local_to_map().
  • Перераховувати шлях після встановлення або руйнування перешкод.
  • Обробляти порожній шлях без зависання та руху крізь стіну.
Не викликай update() після кожного блокування без повторного нанесення
перешкод: перебудова сітки скидає дані про заблоковані точки.

Runner має користуватися відкритим маршрутом. Breaker має вміти дійти
до доступної клітинки біля барикади, зупинитися й атакувати її, а після
руйнування продовжити рух. Вибір барикади/вартості обходу ще не погоджено.
Для тесту пропоную: Runner обходить, Breaker ламає призначену барикаду
на короткому маршруті; якщо ціль недоступна — шукає іншу досяжну ціль.
Один і той самий пошук із барикадами як непрохідними клітинками не реалізує
цю різницю автоматично — потрібна окрема логіка вибору цілі для Breaker.

Офіційний приклад AStarGrid2D:
https://github.com/godotengine/godot-demo-projects/blob/master/2d/navigation_astar/pathfind_astar.gd
Опис властивостей і методів:
https://github.com/godotengine/godot/blob/master/doc/classes/AStarGrid2D.xml

Перевірка: один ворог доходить до бази; стіну обходить; після перекриття
одного проходу Runner переходить на інший; Breaker руйнує тестову барикаду.

ПЛАН Б. ІГРОВІ ОБ'ЄКТИ
Усі наведені далі сцени й скрипти ще потрібно створити через Scene > New
Scene та Attach Script. Назви файлів нижче — запропонована структура.

scenes/enemies/runner.tscn і breaker.tscn:
  Корінь CharacterBody2D, дочірні Sprite2D і CollisionShape2D.
  У Sprite2D > Texture перетягни відповідний PNG з enemies/.
  У CollisionShape2D > Shape створи невелике коло навколо тіла.
  scripts/enemy.gd: здоров'я, швидкість, рух по точках шляху,
  отримання шкоди, смерть, одноразова нагорода, досягнення бази.
  Для Breaker додай стан атаки барикади та затримку між ударами.
  Масштабуй Sprite2D, а не весь фізичний вузол. Орієнтир видимого розміру:
  Runner 48–64 px, Breaker 64–80 px; враховуй прозорі поля PNG.
  Підбери ширину проходів і колайдери так, щоб великі вороги проходили.

scenes/objects/barricade.tscn:
  StaticBody2D, візуальне позначення та CollisionShape2D.
  scripts/barricade.gd: запас міцності, пошкодження, руйнування,
  повідомлення GridNavigation про звільнення клітинки.
  Окремої графіки барикади немає; для прототипу потрібна тимчасова форма.

scenes/towers/machine_gun.tscn і tesla.tscn:
  Node2D, Sprite2D, Area2D з CollisionShape2D для радіуса пошуку ворогів.
  scripts/tower.gd: радіус, шкода, інтервал пострілів, вибір живої цілі.
  Кулемет атакує одну ціль. Для Tesla вид електричної атаки ще треба
  визначити; тимчасову атаку по одній цілі не вважати остаточною механікою.
  Шкоду для першого тесту можна наносити одразу, з коротким ефектом пострілу.
  Окреме обертання ствола кулемета потребує розділення його PNG на частини.
  Орієнтир видимого розміру вежі — 96 px. Така графіка ширша за клітинку:
  для прототипу лиши логічне місце 1 × 1 й перевір, чи сусідні вежі не зливаються.

Налаштуй collision layers/masks узгоджено: вороги стикаються зі стінами
й барикадами; Area2D веж бачить ворогів. Для фізичних стін додай Physics
Layer у TileSet і полігони колізії лише тайлам стін. Це окрема робота від
позначення стін у AStarGrid2D: потрібні обидва налаштування.

ПЛАН В. БУДІВНИЦТВО, ХВИЛІ ТА БАЗА
scripts/build_manager.gd, вузол BuildManager:
  Вибір вежі/барикади, підсвічування клітинки під курсором, перевірка ціни,
  дозволеної зони та зайнятості; створення об'єкта й одноразове списання ціни.
  Заборонити будівництво на Spawn, Base і стінах, а також крізь кнопки HUD.
  Для першого прототипу пропоную заборонити повне перекриття всіх маршрутів:
  тимчасово заблокувати клітинку, перевірити шлях, відкотити при відмові.
  Це правило потребує погодження, бо впливає на роль Breaker.

scripts/wave_manager.gd, вузол WaveManager з Timer:
  Список хвиль: тип ворога, кількість, інтервал появи.
  Створювати ворогів у Spawn і додавати в Enemies.
  Хвиля завершена лише коли всіх запланованих ворогів створено і живих
  ворогів цієї хвилі більше немає. Не запускати хвилю повторно подвійним кліком.
  Для перевірки достатньо трьох хвиль: Runner; суміш; більша суміш.
  Конкретні кількості та характеристики — тестовий баланс, не вимога автора.

scripts/level.gd на Level01:
  Зберігати здоров'я бази, гроші та стан рівня.
  Досягнення бази: один раз зменшити її здоров'я та прибрати ворога,
  не видаючи нагороду за його знищення.
  Перемога: остання хвиля завершена, ворогів немає, база жива.
  Поразка: здоров'я бази <= 0. Після фіналу зупинити спавн, бій і будівництво.

HUD (CanvasLayer): додай Control з Label для здоров'я, грошей і хвилі,
кнопки вибору споруд, Start Wave, Restart та панель перемоги/поразки.
З'єднай сигнали pressed кнопок із відповідними діями через панель Signals.
Restart повинен перезавантажити рівень і відновити початковий стан.

ПЛАН Г. ПЕРЕВІРКА ПОВНОГО РІВНЯ
[ ] F5 відкриває потрібну мапу; вона вміщується у вікно.
[ ] Вороги з'являються хвилями, обходять стіни й доходять до бази.
[ ] Runner обходить барикаду, Breaker може її зруйнувати.
[ ] Будівництво перевіряє зону, зайнятість, гроші й правило перекриття.
[ ] Вежі знаходять ворогів у радіусі, стріляють і завдають шкоди.
[ ] Смерть видає нагороду один раз; прорив завдає шкоди базі один раз.
[ ] Є перемога після останньої хвилі та поразка при знищенні бази.
[ ] Restart працює після обох результатів; немає залишених ворогів/таймерів.
[ ] В Output/Debugger немає помилок під час повного проходження.
