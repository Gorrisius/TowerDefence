# Урок: як турель повертається і стріляє

Мета — зрозуміти один постріл від початку до кінця. Спочатку розберемо поворот, потім частоту стрільби, кулю й ефекти. Кожна частина відповідає на окреме запитання.

Працюй у `towers/rotating_tower/RotatingTurret.cs` та `towers/rotating_tower/rotating_turret.tscn`. [Final_Solution.md](Final_Solution.md) — повний зразок для звіряння. Фрагменти нижче пояснюють частини зразка: не додавай їх удруге, якщо вони вже є у файлі. Назви класів і файлів мають збігатися; дублікати класів створювати не потрібно.

## 1. Що саме має обертатися

Якщо повернути корінь турелі, повернеться й основа. Тому рухомий верх має окремого батька `Turret`:

```text
RotatingTurret (Node2D зі скриптом RotatingTurret.cs)
├── BaseSprite (Sprite2D)
└── Turret (Node2D)
	└── Recoil (Node2D)
		├── GunSprite (Sprite2D)
		├── Lamp (Sprite2D)
		└── Muzzle (Marker2D)
			└── Flash (Sprite2D)
```

Діти успадковують рух і поворот батька. Поворот `Turret` повертає ствол, лампу й дуло разом. Зміщення `Recoil` відсуває ці частини назад під час пострілу, залишаючи вісь обертання на місці.

`Muzzle` — позначка, звідки вилітає куля. Постав її на кінці ствола. `Lamp` і `Flash` спочатку сховай через Visible. Признач текстури з `towers/rotating_tower/assets`: `base.png`, `tower.png`, `lamp.png`, `flash.png`. При Rotation = 0 ствол повинен дивитися праворуч, уздовж +X.

Scale кореня і `Turret` залиш `(1, 1)`. Розмір зображення налаштовуй у Sprite2D. Зміщення й масштаб зі зразка сцени — приклад вирівнювання, а не універсальні числа для будь-якого малюнка.

**Перевір у редакторі:** поверни `Turret` на 45°. Основа стоїть, верх повертається. Поверни Rotation у 0. Для цієї перевірки запуск гри не потрібний.

## 2. Як скрипт знаходить частини сцени

Поля `_turret`, `_recoil` тощо зберігають посилання на вже створені вузли. У `_Ready()` заповнюємо їх:

```csharp
_turret = GetNode<Node2D>("Turret");
_recoil = GetNode<Node2D>("Turret/Recoil");
_muzzle = GetNode<Marker2D>("Turret/Recoil/Muzzle");
_flash = _muzzle.GetNode<Sprite2D>("Flash");
_lamp = _recoil.GetNode<Sprite2D>("Lamp");
```

Шлях рахується від вузла, на якому викликаємо `GetNode`. Перші три виклики починаються від кореня зі скриптом. `_muzzle.GetNode` починається вже від Muzzle, тому достатньо назви його дитини Flash.

**Перевір:** назви в дереві та рядках повинні збігатися, включно з великими літерами. `Node not found` зазвичай означає неправильний шлях або назву.

## 3. Які дані зберігаємо між кадрами

Godot повторно викликає `_PhysicsProcess(double delta)`. Поля класу зберігають значення між викликами, тому турель пам’ятає ціль і залишок часу.

| Поле | Що означає |
|---|---|
| `_target` | Ворог, за яким зараз стежимо |
| `_cooldown` | Секунди до дозволу на наступний постріл |
| `_shotTime` | Секунди до кінця ефектів останнього пострілу |
| `TowerRange` | Радіус пошуку цілі |
| `TurnSpeed` | Швидкість повороту в радіанах за секунду |
| `ShotInterval` | Мінімальний час між пострілами |

`[Export]` показує параметр в Inspector. Значення, збережене в сцені, може відрізнятися від початкового значення в C#. Під час перевірок дивись і на Inspector.

## 4. Як вибрати ціль

Перш ніж читати позицію ворога, перевіряємо, чи він ще існує і чи підходить для стрільби:

```csharp
private bool IsTargetValid(Enemy enemy) =>
	GodotObject.IsInstanceValid(enemy)
	&& enemy.CanBeTargeted
	&& enemy.IsInsideTree()
	&& GlobalPosition.DistanceSquaredTo(enemy.GlobalPosition)
		<= TowerRange * TowerRange;
```

`&&` означає, що потрібні всі умови. Перевірка зупиняється на першому `false`. Тому після невдалого `IsInstanceValid` ми не звертаємося до властивостей видаленого об’єкта. У твоєму Enemy властивість `CanBeTargeted` перевіряє, що ворог живий, не завершив шлях і не очікує видалення.

`DistanceSquaredTo` повертає квадрат відстані, тому й радіус підносимо до квадрата. Для радіуса 220 поріг дорівнює 48400. Так перевіряємо дальність без квадратного кореня.

`FindTarget()` перебирає групу `enemies`. `closest` — найкращий знайдений ворог, `best` — квадрат відстані до нього. Якщо відстані до трьох ворогів 150, 90 і 120, запам’ятаємо першого, замінимо другим і залишимо другого після третьої перевірки.

**Важливо:** `return closest;` стоїть після `foreach`. Усередині циклу він завершить пошук завчасно. `continue` натомість пропускає лише одного ворога і переходить до наступного.

У `_PhysicsProcess` використовуємо пошук так:

```csharp
if (!IsTargetValid(_target))
	_target = FindTarget();

if (_target == null)
	return;
```

Поки поточна ціль підходить, зберігаємо її. Це запобігає постійному перемиканню між близькими ворогами. `return` завершує лише цей виклик методу: наступного фізичного кадру Godot викличе його знову.

## 5. Поворот — це три прості обчислення

Спочатку знайди вектор від турелі до ворога:

```csharp
Vector2 toTarget = _target.GlobalPosition - _turret.GlobalPosition;
float desired = toTarget.Angle();
```

Турель у `(100, 100)`, ворог у `(200, 100)`: різниця `(100, 0)` спрямована праворуч. `Angle()` перетворює напрямок на кут. Праворуч — 0 радіанів, униз — приблизно 1.57 радіана, тобто 90°. Вісь Y на екрані спрямована вниз.

Обидві позиції світові, тому їх можна віднімати навіть за різних батьків у дереві сцени.

Тепер поверни ствол трохи ближче до бажаного кута:

```csharp
float turnThisFrame = TurnSpeed * (float)delta;
_turret.GlobalRotation = Mathf.RotateToward(
	_turret.GlobalRotation, desired, turnThisFrame);
```

`delta` — час фізичного кроку в секундах. При швидкості 4 радіани/с і кроці 1/60 секунди дозволений поворот становить приблизно 0.067 радіана. Множення на `delta` переводить швидкість за секунду в рух за цей крок. `RotateToward` наближає кут до потрібного, не перестрибуючи через нього.

Нарешті обчисли, наскільки ще не довертів ствол:

```csharp
float error = Mathf.Abs(
	Mathf.AngleDifference(_turret.GlobalRotation, desired));
```

`Abs` прибирає знак: важливий розмір похибки, а не сторона. `AngleDifference` правильно враховує межу оберту: між 179° і −179° лише 2°, а не 358°.

**Перевір після складання й налаштування сцени:** постав Turn Speed = 1. Ствол має повертатися повільніше. Потім поверни 4.

## 6. Чому cooldown зменшується

Ми обрали зворотний відлік: 0 означає «готовий», додатне значення — «ще чекаємо».

```csharp
_cooldown = System.Math.Max(0, _cooldown - delta);
```

Після пострілу встановлюємо `_cooldown = ShotInterval`. Для інтервалу 0.5 секунди й умовного кроку 0.1 відлік такий: `0.5 → 0.4 → 0.3 → 0.2 → 0.1 → 0`. `Max` не дозволяє результату стати від’ємним.

Після повороту перевіряємо:

```csharp
if (_cooldown > 0 || error > 0.04f)
	return;
```

`||` означає «або». Не стріляємо, якщо ще перезаряджаємося або недостатньо точно навелися. `0.04` радіана — приблизно 2.3°, обрана допустима похибка.

Ця перевірка стоїть **після повороту**. Якщо поставити її перед ним, під час перезаряджання `return` не дозволить виконати наведення.

**Перевір:** збільш Shot Interval до 2. Постріли стануть рідшими, але ствол повинен без пауз стежити за ворогом.

## 7. Як створити кулю

`PackedScene` — шаблон сцени, а `Instantiate` створює окремий об’єкт із цього шаблону:

```csharp
var bullet = BulletScene.Instantiate<TurretBullet>();
GetTree().CurrentScene.AddChild(bullet);
bullet.Launch(
	_muzzle.GlobalPosition,
	Vector2.Right.Rotated(_turret.GlobalRotation),
	Damage);
_cooldown = ShotInterval;
```

Кулю додаємо до поточної сцени, щоб вона летіла незалежно від подальших поворотів турелі. Дитина вузла Turret поверталася б разом із ним навіть у польоті.

`Vector2.Right` — напрямок `(1, 0)`. Повертаємо його на кут ствола й отримуємо напрямок польоту. `Launch` отримує позицію старту, напрямок і шкоду. Світову позицію задаємо після `AddChild`, коли батько кулі вже відомий.

Створи `towers/rotating_tower/bullet.tscn`:

```text
TurretBullet (Node2D зі скриптом TurretBullet.cs)
├── Sprite2D (текстура assets/bullet.png)
└── Impact (Sprite2D, текстура assets/flash.png, Visible вимкнено)
```

Після успішного Build вибери корінь турелі й перетягни цю сцену в **Bullet Scene**. Порожнє поле спричиняє спрацювання перевірки в `_Ready()` і вимкнення фізичної обробки турелі.

**Перевір:** куля виникає біля кінця ствола. Якщо в центрі — перевір Muzzle. Якщо закручується за туреллю — перевір батька кулі.

## 8. Що означають дивні числа у віддачі

`_cooldown` керує частотою пострілів. `_shotTime` потрібний окремо, бо світло і віддача мають закінчитися швидше. Після пострілу:

```csharp
_shotTime = 0.12;
_flash.Visible = true;
_lamp.Visible = true;
```

На початку `_PhysicsProcess`, до перевірки наявності цілі, оновлюємо ефекти:

```csharp
_shotTime = System.Math.Max(0, _shotTime - delta);
_recoil.Position = new Vector2(-3 * (float)(_shotTime / 0.12), 0);
_flash.Visible = _shotTime > 0.065;
_lamp.Visible = _shotTime > 0;
```

Ділення залишку часу на повну тривалість 0.12 дає частку від 1 до 0. Множення на −3 перетворює її на зміщення назад:

| Залишок часу | Частка | Позиція Recoil по X |
|---|---|---|
| 0.12 с | 1 | −3 пікселі |
| 0.06 с | 0.5 | −1.5 пікселя |
| 0 с | 0 | 0 пікселів |

Це локальна `Position`: «назад» відносно ствола, навіть коли він повернутий. Формула передбачає початкову позицію Recoil `(0, 0)`. У повному зразку позиція вперше оновлюється наступного кроку після пострілу, тому початковий зсув буде трохи меншим за 3 пікселі.

Лампа світиться, поки залишився час. Спалах гасне раніше: `0.12 − 0.065 = 0.055` секунди після пострілу, приблизно. Точний момент залежить від фізичного кроку.

Числа 3, 0.12 і 0.065 — налаштування вигляду. Після розбору їх можна винести в константи `RecoilDistance`, `RecoilDuration` і `FlashCutoff`.

**Перевір:** після смерті останнього ворога світло все одно гасне, а ствол повертається на місце. Якщо ні — оновлення ефектів, імовірно, стоїть після раннього `return`.

## 9. Як летить куля

У `TurretBullet.Launch`:

```csharp
GlobalPosition = origin;
_direction = direction.Normalized();
GlobalRotation = _direction.Angle();
_damage = damage;
_launched = true;
```

`Normalized` залишає напрямок і робить довжину вектора рівною 1. Тоді швидкість визначає лише Speed. `GlobalRotation` повертає зображення носом уперед.

Рух за крок:

```csharp
Vector2 step = _direction * Speed * (float)delta;
```

При 700 пікселях/с і кроці 1/60 це приблизно 11.7 пікселя. Якщо влучання немає, додаємо step до GlobalPosition. Куля не переслідує ворога: вона зберігає початковий напрямок.

`_age += delta` накопичує час польоту. При досягненні Lifetime видаляємо кулю через `QueueFree()` і завершуємо виклик. Код руху повинен стояти після закриття цього блоку, а не всередині нього після `return`.

## 10. Як куля завдає шкоди

У ворогів цього проєкту немає CollisionShape2D. Тому уявляємо навколо кожного коло радіуса HitRadius і перевіряємо, чи перетнув його шлях кулі за крок.

Перевіряємо весь відрізок руху: лише кінцева точка може пропустити швидку кулю, яка вже перелетіла через ворога. З усіх перетинів вибираємо найближчий. [Окремий розбір формули з числами](Hit_Detection.md) пояснює b, c і discriminant.

Після влучання:

1. Переносимо кулю в точку зіткнення.
2. Встановлюємо `_hit = true`, скидаємо `_age = 0` для ефекту.
3. Один раз викликаємо `first.TakeDamage(_damage)`.
4. Ховаємо Sprite2D, показуємо Impact.
5. За 0.12 секунди зменшуємо прозорість Impact, збільшуємо його розмір і видаляємо вузол.

На наступних кроках гілка `if (_hit)` обробляє лише ефект і завершується через `return`, тому повторної шкоди немає. Турель сама TakeDamage не викликає.

Цей варіант не враховує стіни й рух ворога між двома фізичними кроками: коло береться в його поточній позиції.

## 11. Чому порядок рядків важливий

```text
Оновити таймери й ефекти
→ перевірити ціль, за потреби знайти нову
→ немає цілі? завершити цей виклик
→ повернути ствол
→ перезаряджаємося або не навелися? завершити цей виклик
→ створити кулю і запустити таймери пострілу
```

Цей порядок дозволяє ефектам завершуватися без цілі, а стволу — повертатися під час перезаряджання.

## 12. Перевір у грі по одній ознаці

Спочатку Build: помилка навіть в іншому C# файлі блокує складання. Для скриптів зразка достатньо `using Godot;`; System.Math записаний повністю. Не додавай `using System.Numerics;`: він містить інший Vector2 і створює неоднозначність.

Відкрий свій рівень із ворогами й додай турель із `towers/rotating_tower/rotating_turret.tscn` біля маршруту. Перевір Bullet Scene в Inspector. Запускай відкриту сцену через F6. Старий `demo.tscn` посилається на папку `towers/rotating`; для його використання спочатку перепризнач сцену турелі на актуальний шлях.

| Дія | Очікуваний результат |
|---|---|
| Ворог входить у радіус | Верх повертається, основа стоїть |
| Shot Interval = 2 | Стріляє рідше, стежить без пауз |
| Turn Speed = 1 | Чекає, доки наведе ствол |
| Speed кулі = 150 | Шкода при влучанні; можливі промахи |
| Після пострілу ціль зникла | Світло гасне, віддача завершується |
| Куля промахнулася | Зникає після Lifetime |

Змінюй один параметр за раз і повертай його після перевірки. Цей список описує ручні перевірки; він не означає, що твоя поточна версія вже їх пройшла.
