Як працювати з цими двома файлами
enemy.txt — завдання, пояснення й порядок дій. Пиши код сам за описом.
enemy_solved.txt — повна реалізація тих самих завдань для звіряння.
Код із розв'язку не підключений до гри автоматично. Ти сам створиш два
скрипти, допишеш наявний третій і підключиш їх у редакторі.

Мета уроку: п'ять Runner з'являються по одному раз на дві секунди,
знаходять прохід навколо стін, доходять до Base і зникають. В Output
збільшується лічильник прибулих. Це ще не шкода базі й не бойова система.
Значення 5, 2 секунди та швидкість 100 — навчальні параметри.

УРОК ПРИВ'ЯЗАНИЙ ДО ТВОГО ПРОЄКТУ
Перевірено поточні файли:

  res://enemies/runner.png — зображення ворога.
У Level01 уже є Ground, Walls, BuildZones, Details, Spawn, Base, Camera2D.
Spawn зараз у (94,417), Base у (1441,416). Це світові позиції, а не індекси
клітинок. За поточних трансформацій це клітинки (1,6) та (22,6).
Між ними є прохід. Залиш свою мапу, не перемальовуй її під старий приклад.

У проєкті вже обрано C#, є game-4.csproj. Усі приклади цього уроку — C#.
Регістр важливий: Enemy.cs і клас Enemy, GridNavigation.cs і клас
GridNavigation. Не створюй другий клас GridNavigation в іншій папці.

1. ЯК ПРАЦЮВАТИМЕ СИСТЕМА
Три окремі відповідальності:
  GridNavigation — читає Ground/Walls і повертає список точок маршруту.
  Enemy — рухається по отриманих точках і повідомляє про прибуття.
  EnemySpawner — створює ворогів за таймером та рахує прибулих.

Порядок викликів:
  Level01._Ready → побудова сітки → StartSpawning → FindPath → SpawnOne
  → Enemy.Setup → багато викликів _PhysicsProcess → Finish → сигнал
  ReachedBase → OnEnemyReachedBase → видалення ворога.

Маршрут шукатимемо через AStarGrid2D. Це об'єкт у коді, а не вузол,
який треба додати через «+». Для уроку кожна клітинка Walls повністю
непрохідна; будь-яка клітинка без Ground теж непрохідна. Details і
BuildZones не блокують рух. Картинка стіни на Ground не вважатиметься
стіною: перешкоди потрібно малювати на Walls.

Ворог тут Node2D: рух керується шляхом, фізичне ковзання й зіткнення
не використовуються. Вороги можуть перекривати один одного. Навіть якщо
намальована стіна має частковий полігон колізії, пошук блокує всю клітинку.
Цього достатньо для першого уроку. Вузькі проходи залишай достатніми для
картинки ворога. Динамічні барикади й перерахунок маршруту будуть окремо.

5. ЗАВДАННЯ 1 — ПОБУДУЙ НАВІГАЦІЮ У GridNavigation.cs
Відкрий наявний res://levels/GridNavigation.cs. Залиш клас
public partial class GridNavigation : Node2D. Порожній _Process прибери.
До using Godot додай using System.Collections.Generic — для List<Vector2>.
Усі поля й методи далі пиши ВСЕРЕДИНІ фігурних дужок цього класу.

5.1. Поля, тобто пам'ять об'єкта:
  _grid — private readonly AStarGrid2D, одразу створити через new();
  _ground — private TileMapLayer;
  _walls — private TileMapLayer.
private означає, що ці дані використовуються всередині класу.
readonly забороняє замінити посилання _grid, але дозволяє налаштувати сітку.

5.2. У public override void _Ready() отримай потрібні вузли:
  GetNode<TileMapLayer>("Ground") записати у _ground;
  аналогічно "Walls" у _walls.
Шлях відраховується від Level01, адже скрипт прикріплений саме до нього.

5.3. Отримай Rect2I region через _ground.GetUsedRect().
Це прямокутник, який охоплює намальовану підлогу; всередині можуть бути
дірки. Якщо Size.X або Size.Y <= 0, виведи GD.PushError і зроби return.
Не продовжуй побудову порожньої сітки.

5.4. Присвой _grid.Region отриманий region. Задай
DiagonalMode = AStarGrid2D.DiagonalModeEnum.Never, потім виклич Update().
Так ворог ходитиме лише вгору, вниз, ліворуч і праворуч.
Після позначення перешкод Update() повторно не викликай: він скине їх.      //  я це не робив бо не хочу щоб вони тільки так і ходили

5.5. Два вкладені цикли for мають перебрати прямокутник:
  y від region.Position.Y, поки y < region.End.Y;
  x від region.Position.X, поки x < region.End.X.
Для кожної клітинки створи Vector2I cell з x та y.
Перевір дві умови:
  noFloor: _ground.GetCellSourceId(cell) == -1;
  wall: _walls.GetCellSourceId(cell) != -1.
Передай noFloor || wall у _grid.SetPointSolid(cell, ...).
-1 означає, що тайла немає. || означає «або». Якщо немає підлоги АБО
є стіна, клітинка непрохідна. Одна лише наявність фізичної колізії
в TileSet не заповнює AStarGrid2D — тому ми робимо цю перевірку самі.

5.6. Напиши окремий метод із сигнатурою:
  public List<Vector2> FindPath(Vector2 startWorld, Vector2 finishWorld)
Він має ПОВЕРНУТИ список світових точок, а не рухати ворога.
Спочатку створи порожній List<Vector2> result.
Для обох вхідних позицій виконай два перетворення:
  _ground.ToLocal(...) переводить світову позицію в координати Ground;
  _ground.LocalToMap(...) визначає клітинку цієї локальної позиції.
Збережи результати як Vector2I start та finish.

5.7. Через IsInBoundsv перевір обидві клітинки. Якщо хоч одна поза сіткою,
виведи помилку і поверни result. Тільки ПІСЛЯ цієї перевірки перевір
IsPointSolid для обох. Якщо старт або фініш заблоковані — теж порожній result.
Це захищає від помилок, якщо ти переставиш маркери.

5.8. Отримай клітинки через _grid.GetIdPath(start, finish).
Якщо Count == 0, виведи повідомлення «немає маршруту» і поверни result.
Інакше перебери клітинки циклом foreach:
  MapToLocal(cell) дає центр клітинки в координатах Ground;
  ToGlobal(...) переводить його у світові координати;
  додай отриману точку в result через Add.
Наприкінці додай finishWorld: ворог має дійти саме до Base, навіть якщо
маркер стоїть трохи збоку від центру клітинки. Поверни result через return.
Першою точкою буде центр стартової клітинки; з маркера Spawn ворог спершу
зробить короткий рух до цього центру.

5.9. Наприкінці _Ready, ПІСЛЯ циклів заповнення сітки, отримай
GetNode<EnemySpawner>("EnemySpawner") і виклич StartSpawning(this).
this — поточний GridNavigation. Передаємо його спавнеру для пошуку шляху.
Метод StartSpawning напишеш у розділі 7. До завершення всіх трьох класів
компілятор може повідомляти про відсутні методи — це проміжний стан.

Чому запуск звідси? _Ready дітей викликається перед _Ready батька.
Якби спавнер починав роботу у своєму _Ready, сітка батька ще була б порожня.
Тому батько спершу готує навігацію й тільки потім запускає спавнер.

https://docs.godotengine.org/en/stable/classes/class_tilemaplayer.html

6. ЗАВДАННЯ 2 — НАВЧИ ОДНОГО ВОРОГА ЙТИ У Enemy.cs
Відкрий res://enemies/Enemy.cs. Клас: Enemy : Node2D, обов'язково partial.
Підключи using Godot та using System.Collections.Generic.
Порожні методи шаблону можна прибрати: потрібні методи опишемо нижче.

6.1. Створи експортовану властивість Speed типу float, початково 100.0f.
Форма властивості: [Export] public float Speed { get; set; } = 100.0f;
[Export] дасть редагувати швидкість в Inspector. f означає число типу float.

6.2. Оголоси сигнал: [Signal] public delegate void ReachedBaseEventHandler();
Це повідомлення для інших об'єктів: «я дійшов». Воно не змінює здоров'я бази.

6.3. Додай приватні поля:
  _path — List<Vector2>, початково новий порожній список;
  _targetIndex — int, індекс поточної цілі;
  _finished — bool, чи завершив ворог рух.
Індекси списку починаються з 0. Останній доступний індекс — Count - 1.

6.4. Напиши public void Setup(Vector2 spawnPosition, List<Vector2> path).
Присвой GlobalPosition стартову позицію. Зроби власну копію path через
new List<Vector2>(path). Обнули _targetIndex і встанови _finished=false.
Якщо список порожній або Speed <= 0: виведи GD.PushError, вистав
_finished=true й виклич QueueFree(). Не повідомляй про прибуття у цьому
випадку: це неправильна конфігурація, а не успішний рух.

6.5. Напиши public override void _PhysicsProcess(double delta).
Godot викликає його регулярно. delta — тривалість кроку в секундах.
Якщо _finished або список порожній — return.
Обчисли float remaining = Mathf.Max(Speed, 0.0f) * (float)delta.
Це кількість пікселів, яку ворог може пройти за цей крок.
При 100 px/s і delta=0.02 він має пройти 2 px, а не 100 px за кадр.

6.6. Напиши цикл while: поки remaining > 0 і _targetIndex < _path.Count.
Візьми target = _path[_targetIndex]. Визнач distance через
GlobalPosition.DistanceTo(target).
Якщо distance <= remaining:
  — постав GlobalPosition точно в target;
  — відніми distance від remaining;
  — збільш _targetIndex на 1.
Інакше:
  — присвой GlobalPosition результат GlobalPosition.MoveToward(target, remaining);
  — встанови remaining=0, бо бюджет руху на цьому кроці використано.
Навіщо цикл? Якщо до точки залишився 1 px, а бюджет 3 px, ворог пройде
ще 2 px до наступної точки. Так на повороті не губиться частина руху.
Якщо дві точки однакові, distance=0, але індекс зростає — цикл не зависне.

6.7. Після циклу перевір _targetIndex >= _path.Count і виклич Finish().
Не читай _path[_targetIndex] після досягнення Count: такої точки вже немає.

6.8. Напиши private void Finish(). Якщо _finished — return.
Інакше спочатку _finished=true, потім EmitSignal(SignalName.ReachedBase),
потім QueueFree(). Прапорець не дозволяє двічі повідомити про прибуття.
QueueFree видалить весь екземпляр Enemy разом зі Sprite2D наприкінці кадру.
Сцену runner.tscn на диску це не видаляє.

Довідки:
https://docs.godotengine.org/en/stable/classes/class_vector2.html
https://docs.godotengine.org/en/stable/classes/class_node.html

7. ЗАВДАННЯ 3 — СТВОРЮЙ ВОРОГІВ У EnemySpawner.cs
Клас EnemySpawner : Node, partial. Підключи ті самі два using.

7.1. Додай три властивості з [Export], public та { get; set; }:
  EnemyScene — PackedScene, початково не призначена;
  SpawnCount — int, початково 5;
  SpawnInterval — double, початково 2.0.
PackedScene — збережений шаблон сцени, а не живий ворог на мапі.

7.2. Поля private:
  _timer — Timer;
  _enemies — Node2D;
  _spawnPosition — Vector2;
  _path — List<Vector2>, одразу порожній список;
  _spawned та _arrived — int;
  _started — bool.
Лічильники стартують із 0, bool — із false за правилами C#.

7.3. Напиши public void StartSpawning(GridNavigation navigation).
Якщо _started — return, щоб повторний виклик не підключив таймер двічі.
Якщо EnemyScene == null, SpawnCount <= 0 або SpawnInterval <= 0,
виведи GD.PushError з підказкою перевірити Inspector і зроби return.

7.4. Отримай _timer через GetNode<Timer>("SpawnTimer") від самого спавнера.
Через параметр navigation отримай Enemies, Spawn, Base — це діти Level01.
Для Enemies використовуй GetNode<Node2D>, для маркерів GetNode<Marker2D>.
Збережи Spawn.GlobalPosition у _spawnPosition. Передай її та
Base.GlobalPosition в navigation.FindPath і запиши результат у _path.
Якщо _path.Count == 0 — return. Таймер у цьому випадку не запускаємо.

7.5. Після перевірки шляху встанови _started=true.
Задай _timer.WaitTime = SpawnInterval і _timer.OneShot=false.
Підключи подію через _timer.Timeout += SpawnOne; тут БЕЗ дужок після
SpawnOne: передаємо метод для майбутнього виклику.
Потім SpawnOne(); уже З дужками — створюємо першого ворога зараз.
Якщо _spawned < SpawnCount, виклич _timer.Start().
Не використовуй одночасно Autostart і ручне підключення через редактор:
у цьому уроці всі ці дії виконує код.

7.6. Напиши private void SpawnOne().
Якщо _spawned >= SpawnCount, виклич _timer.Stop() і return.
Створи Enemy через EnemyScene.Instantiate<Enemy>().
Додай його через _enemies.AddChild(enemy).
Підключи enemy.ReachedBase += OnEnemyReachedBase.
Виклич enemy.Setup(_spawnPosition, _path).
Збільш _spawned і виведи GD.Print із поточною кількістю.
Якщо тепер _spawned >= SpawnCount — зупини таймер.

Порядок важливий: Instantiate створює об'єкт, AddChild додає його в світ,
а Setup після цього задає GlobalPosition і маршрут. Якщо налаштувати
глобальну позицію до додавання, трансформація майбутнього батька може
змінити фактичну позицію. Якщо забути AddChild, ворога не буде видно.
Зупинка таймера не зупиняє рух уже створених ворогів.

7.7. Напиши private void OnEnemyReachedBase().
Збільш _arrived і виведи GD.Print, наприклад «До бази дійшло 1/5».
Для підстановки чисел використай рядок виду $"... {_arrived}/{SpawnCount}".
Це реакція на сигнал; ворог сам видалить себе у Finish().
